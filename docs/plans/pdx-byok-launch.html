Why the current site is unusable

Confirmed failure: three consecutive requests to https://noteformula.cooldash.xyz/api/health returned 503 no available server.
  • Coolify reports the application as running:unhealthy.
  • Web listens on container port 3000, but the stored domain omits the internal :3000 routing suffix.
  • The generated host route has no explicit Web load-balancer port, and stale resource labels still target port 80.
  • The deployed image is behind the repository. Google, GitHub, and Resend are empty and intentionally deferred for the email-only launch.
  • pdx.sdey.me now resolves to the Coolify host and serves valid HTTPS.

Coolify requires a domain such as https://pdx.sdey.me:3000 when the Compose service listens on port 3000. The suffix selects the internal port. Public traffic still uses HTTPS port 443.

Routing is the first confirmed fault, not the only possible one. The replacement must still prove Neon, Redis, Worker callbacks, Chromium, and R2 from inside the clean stack.

Credential record

Store one credential per user: provider slug, normalized base URL, model ID, versioned encrypted envelope, masked key hint, and verification timestamps. Add an onboarding-dismissal timestamp to User.

Encryption and retrieval

Use AES-256-GCM with a dedicated Coolify secret. The Worker requests a credential by materialId through a private endpoint authenticated by the existing Worker secret. Web derives ownership, decrypts in memory, and returns a no-store response. Queue payloads never contain the key.

Accurate user note: “Your API key is encrypted at rest, never shown again after saving, and used only for your generation requests. Your prompts and study content are sent directly to the provider you choose.”

Do not say "hashed." Hashing is one-way, while provider calls require the original key.

Provider setup

Ship OpenAI, OpenRouter, DeepSeek, and Groq presets plus Custom. Presets supply an editable model default. Saving runs a tiny structured-output request through @ai-sdk/openai-compatible.

Custom URL policy

Custom endpoints accept HTTPS public hosts only. Reject credentials in URLs, private and metadata networks, forbidden DNS results, cross-origin redirects, arbitrary headers, oversized responses, and slow connections. Repeat DNS safety checks when generation starts.

Remove active billing without deleting history

  • Delete payment-link, webhook, transaction, coupon, and credit endpoints.
  • Remove Dodo Payments, standardwebhooks, product IDs, checkout links, and billing environment variables.
  • Remove credit gates, reservations, deductions, and estimated-credit UI.
  • Replace Billing, Redeem, and Transactions settings with provider configuration.
  • Keep /pricing as a $0 BYOK explanation in navigation and the sitemap. Remove its plans, checkout, and purchase UI.
  • Keep historical billing tables and columns dormant. No release-time destructive migration.

Compose and database

The production stack has four roles: private Redis, a one-shot migration job, public Web on container port 3000, and private Worker. Web and Worker wait for Redis and migration completion. Worker also waits for healthy Web.

The repository currently has no Prisma migration history. First compare the live Neon schema, create and mark an existing-schema baseline, test it on an isolated database, then add the credential migration. Only after that should Compose run prisma migrate deploy.

  • No public Redis, Worker, or migrate ports.
  • Named volumes for Redis and Worker scratch space.
  • Web health checks both process and database.
  • Worker health checks authenticated Redis connectivity.
  • BYOK_ENCRYPTION_KEY exists only on Web.
  • No server-funded AI or payment secrets remain.
